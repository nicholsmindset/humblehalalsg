## Serving design
- Current editorial templates use dedicated units without the retired /api/ads API.
- Articles: >=600 body words, >=350 words and two body paragraphs before each ad, >=two sections between ads, maximum three. No ads after the final section or at newsletter/lead/pull-quote breaks. Noindex posts excluded.
- Home: one unit after latest guides. Blog/category lists: one full-width unit after six cards, only when at least nine cards exist.
- Selected tools: one unit after content. Explicit allowlist in lib/editorial-ads.ts.
- ALL Quran pages (index, surahs and search) remain ad-free. Devotional readers, prayer tools, maps, contact/legal/admin and other unlisted surfaces do not receive placements.
- Units reserve 280px plus label/padding before hydration; variable-height Google creatives can still be taller. Measure field CLS after real serving begins.
- The AdSense tag initializes Google’s regional CMP unless the visitor has an explicit site-level opt-out; units are queued only within 300px of the viewport. Google applies regional consent before serving. Zero-width units are deferred. No timed ad refresh. New route = new ad element.
- One deduplicated loader; preview/localhost use data-adtest=on. Google regional CMP handles the additional regional consent flow. The site's custom banner is not a replacement for a certified CMP.
- Consent refusal, unfilled units and loader failures show a first-party guide recommendation in the reserved space. No site consent grant is assumed or written. Footer Cookie settings permits a site-level opt-out; Google provides its regional revocation link.
- Existing tracking no longer labels a queued request as an AdSense impression; filled status is observed separately. Google AdSense reporting remains authoritative for billable impressions/revenue.

## 7 October: production deployment regression
The GitHub prebuilt release after PR #431 replaced the remotely built working deployment. NEXT_PUBLIC_ADSENSE_CLIENT was stored as a Vercel Sensitive/Secret variable: production environment pulls exported it as an empty string. Next.js froze that empty string into the client bundle, so the released site rendered no placements or AdSense loader. A successful `vercel env update` did not fix the variable's storage type.

Restored the working production deployment immediately; the live article then received HTTP 200 from Google's ad endpoint and its first unit reported data-ad-status=filled with a visible creative. The account's site list showed humblehalal.com Ready / ads.txt Authorized, and Policy center showed no current serving issues.

Recreated only this public publisher variable as non-sensitive configuration and verified that a fresh production environment pull contains ca-pub-7886081043408699. No credentials were changed. Added a prebuild check and a GitHub production deployment check requiring the publisher to match public/ads.txt, so an empty or wrong publisher fails before promotion. Preview and ordinary test builds can still omit ads. Quran exclusions and consent behavior are unchanged.
